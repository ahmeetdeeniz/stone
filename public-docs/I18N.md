# Internationalization

English is the canonical resource and default UI locale. Turkish is bundled with the application;
there is no runtime translation download and localization never blocks offline startup.

## Runtime behavior

- Supported effective locales are `en` and `tr`.
- The preference is `system`, `en`, or `tr`. System detection maps `tr`, `tr-TR`, and `tr-CY` to
  Turkish and all unsupported or malformed values to English.
- Mobile stores `stone.locale.preference.v1` in SecureStore. Windows stores the same versioned key
  in localStorage. Read/write failures preserve the current session and safely fall back to System
  after restart.
- The preference exists before authentication and is intentionally not synced or exported.
- English is the per-key fallback when a Turkish entry is unavailable.

## Adding or changing copy

1. Add the English key to `packages/i18n/src/en.ts`.
2. Add the exact same key to `packages/i18n/src/tr.ts`.
3. Native Android widget strings must remain in parity between `values/strings.xml` and
   `values-tr/strings.xml`; iOS widget strings use the matching English/Turkish dictionary keys.
4. Keep every `{{parameter}}` name identical between locales.
5. Use the typed `t`/`tp` provider APIs in UI code. Do not index resources directly.
6. Use shared formatters for dates, instants, relative dates, numbers, percentages, file sizes,
   durations, recurrence, priorities, states, project health, and release labels.
7. Run `pnpm verify:i18n`, affected tests, typecheck, lint, and format checks.

`pnpm verify:i18n` checks TypeScript, Android XML, and iOS native widget key parity.

`verify:i18n` rejects duplicate keys, resource or interpolation mismatch, and static user-facing
copy in selected mobile/desktop UI boundaries. Its allowlist is limited to product/technology
names, technical commands, platform labels, and compact symbolic controls. An exception should be
rare, explicit, and reviewable.

## Formatting and calendar rules

Date-only values are parsed at UTC noon to avoid timezone drift. Instants always require an
explicit IANA timezone. Week-based UI starts on Monday in both languages. Calendar category and
recurrence labels are presentation strings; stored enum values remain stable English machine
identifiers.

Tests that depend on “now” must inject or pin the reference date. Never make a locale test depend on
the developer machine’s current clock, timezone, or language.

## Data boundary

Localization applies only to Stone-owned presentation:

- Never translate or rewrite Markdown, note/project/task/event titles, descriptions, frontmatter,
  tags, filenames, paths, repository names, branch names, URLs, imported/exported records, or sync
  payloads.
- Locale switching must not modify SQLite, Firestore, Storage, outbox, revisions, conflicts,
  backups, or workspace exports.
- MCP tool names, input/output schemas, scope identifiers, enum values, audit records, and machine
  error contracts remain stable and locale-neutral. Human-facing MCP client copy defaults to
  English.

When a new persisted enum is introduced, keep its machine value language-neutral and add separate
English/Turkish presentation keys. Do not store a translated label.

## Manual QA

Automated checks cannot certify clipping, mixed-language transitions, screen-reader cadence,
keyboard overlap, or runtime credential flows. Maintainers keep the private owner checklist outside
the public repository boundary and must record each device/surface result as pass, fail, or not
run. Never infer a manual pass from unit tests or screenshots.
